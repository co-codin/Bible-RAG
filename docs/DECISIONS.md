# Decisions log

- **Python, not Go**, for the main app: DeepEval and bge-m3 tooling are Python-native. Go stays optional (`go-embed-worker/`).
- **Quran added** alongside the Bible; `corpus` column distinguishes them.
- **Translations**: Bible KJV (EN), CUV Simplified (ZH), Synodal (RU). Quran Pickthall 1930 (EN, PD), Ma Jian (ZH, copyrighted → not committed), Sablukov 1878 (RU, PD).
- **Phase 1 = EN + ZH only.** KJV and CUV share numbering, so no `verse_map` yet. Note: KJV 31,102 vs CUV 31,103 verses — ingest must report mismatches.
- **Native numbering + `canon_ref`**: precompute `canon_ref` at ingest time instead of joining at query time (scripture is read-only).
- **Russian later**: Synodal Psalms use LXX numbering (KJV Ps 23 = RU Ps 22), plus differences in Numbers, Job, Romans → needs `verse_map`.
- **Frontend first**, using a mock API client, then wire to FastAPI.
- **Milvus instead of Postgres/pgvector** (2026-10-30): native dense + sparse hybrid search with RRF; bge-m3 outputs both, which also solves Chinese keyword search (no zhparser). Two collections: `chunks` (dense + sparse, searched) and `passages` (one row per verse, filter lookups by `canon_ref` / `parent_key`; tiny placeholder vector because Milvus requires one).
- **Chunking v1** (2026-11-02): 3-verse sliding windows, stride 2, per translation and per chapter (chapter = `parent_key`). Neighbouring windows overlap by one verse; the last window is pulled back to end on the final verse; chapters with ≤3 verses are one chunk. `context_prefix` is a plain `"<book> <chapter>"` header (rule id `book_chapter_header.v1`); LLM-written prefixes are a later experiment behind `--contextual`. ~36.7k chunks for KJV + CUV + Quran EN/ZH.
- **Embedding pipeline**: producer (chunking) → embedder → writer (upsert 512) on threads with bounded queues, so chunking and Milvus writes overlap the model forward pass and memory stays bounded (back-pressure). Upserts by pk + skipping pks already present make runs idempotent and resumable. fp16 on GPU, fp32 on CPU.
- **Index versioning** (2026-11-02): the Milvus Lite file is a build artifact (about an hour of CPU embedding), so it is shipped pre-built from a Hugging Face dataset repo (`make fetch-index`, `HF_INDEX_REPO`, default `etsin-ai/bible-rag-index`) instead of being rebuilt on every machine (upload `.milvus/manifest.json` plus the `.milvus/bible_rag.db/` folder; Milvus Lite stores the db as a directory, ~320 MB). A full `ingest.chunks` run writes `.milvus/manifest.json` with a sha256 **fingerprint** of everything that determines the vectors: bge-m3 name + pinned HF revision, window/stride, context-prefix rule id, and the sha256 of each input JSONL. The API calls `bible_rag.index_manifest.check()` at startup and refuses to serve from a mismatched index (`make index-check` does the same from the shell). Change any of those inputs → rebuild and re-upload. Bump `CONTEXT_PREFIX_RULE` when the prefix rule changes.
